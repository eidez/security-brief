## 二、学术前沿

### Carried-Over and Agent-Native Threats in the Supply Chain of LLM Agent Skills
- 作者：Kaixuan Li, Wenbo Guo, Sen Chen, Yang Liu
- 分类：cs.CR, cs.SE　｜　2026-11-23　｜　[原文](https://arxiv.org/abs/2611.30932v1)
- 一句话结论：首个覆盖 4.8 万个 agent skill 的供应链实证：依赖带来的 CVE 大多根本打不到（仅 3.0% 可被 agent 输入触达），真正的风险是作者自己写的第一方代码，以及把 skill 参数交给 shell 执行。
- 为什么值得看：结论反直觉且可执行——49.6% 的可解析依赖技能依赖带已知 CVE 的版本，且 78.3% 是「发布即已脆弱」，但这些 CVE 只有 3% 可达；相反 22 个抽样第一方缺陷里有 21 个被端到端打通。也就是说，按依赖告警排序做安全治理基本是白忙，应该优先治第一方代码，并禁止运行时把参数过 shell。

### SALSA: Sampling Adversarial Suffixes from Learned Distributions for LLM Safety Assessment
- 作者：Shivank Rajput, Himanshu Singh, A. V. Subramanyam
- 分类：cs.CL, cs.CR　｜　2026-11-24　｜　[原文](https://arxiv.org/abs/2611.33030v1)
- 一句话结论：把 GCG 式「对每个 prompt 现场优化后缀」换成「先学一个越狱后缀分布、再采样」，单次生成从 3.46 秒降到 0.04 秒，黑盒迁移上 GPT-3.5-Turbo 达 99%、GPT-4o 仍有 45%。
- 为什么值得看：越狱正从「高成本定向攻击」变成「低成本批量探测」，防守方评估模型安全时的成本结构彻底变了。对做红队或安全评测的人，这是需要重新对齐的新基线数值（99% / 45%）。

### SwarmLeak: Does Coordination Improve Privacy Attacks on LLM Agents?
- 作者：Asma Farajidizaji, Vyas Raina, Vatsal Raina, Ivaxi Sheth
- 分类：cs.CR, cs.CL　｜　2026-11-24　｜　[原文](https://arxiv.org/abs/2611.31791v1)
- 一句话结论：多人协作攻击并不比单人更强：24 个群聊场景下，4 人蜂群在任何 victim 上都不优于单攻击者，而换一个 victim 模型就能让泄露率从 0% 变到 99.4%。
- 为什么值得看：两个可操作的结论：其一，防护资源该投在「把哪个模型放进群聊」，而不是假设对手会组团；其二，攻击者检索到受保护数据 64.3% 但真正说出来只有 0.6%，说明「检索 ≠ 披露」，在策略层做输出审查有实际空间。

### Per-Attack Blocking Hides Catalog Vulnerability: A Weakest-Link Analysis of Tool Manifests
- 作者：Karthik Karunanithi
- 分类：cs.CR, cs.AI　｜　2026-11-23　｜　[原文](https://arxiv.org/abs/2611.31338v1)
- 一句话结论：「单次攻击拦截率 92%」是个会骗人的指标：工具目录越大，存在一条被放行的外泄路径的概率趋近 100%，200 个工具时已达 99%，组合工具毫无保护作用。
- 为什么值得看：如果你给 agent 配了权限清单，不要用「拦住了多少攻击」自证安全，要按目录级漏洞率评估最弱那条策略。更麻烦的是「作者效应」：15 个模型写的策略错误高度聚簇，200 个工具的实际独立性只相当于约 5 个决策——工具数量不是安全裕度。

### POMA: Beyond Final Flags -- Process-Level Evaluation of Base LLMs in Vulnerability Exploitation
- 作者：Gufeng Zhang, Yiru Zhao, Shengyu Liu, Weichen Yan
- 分类：cs.CR, cs.SE　｜　2026-11-23　｜　[原文](https://arxiv.org/abs/2611.30590v1)
- 一句话结论：用过程级指标替代「过/不过」，在 55 道 CTF Pwn 与 10 个真实漏洞复现上测出：模型能力沿「漏洞知识 → 可执行实现 → 目标状态验证 → 失败定位 → 精确修复」逐段衰减。
- 为什么值得看：以后看到「某模型能自动挖洞/打漏洞」的宣传，先分清那是 base model 的能力还是 agent 脚手架堆出来的——这篇给出了把两者拆开测量的方法，也是比「最终 flag」更有诊断价值的评测范式。

### Aftershock: Yesterday's Linux Kernel Bugs, Tomorrow's Android Exploits
- 作者：Kareem Shehada, Zhiyun Qian
- 分类：cs.CR, cs.OS　｜　2026-11-23　｜　[原文](https://arxiv.org/abs/2611.31547v1)
- 一句话结论：端到端流水线把「上游 Linux 补丁 → Android 本地提权 exploit」自动化：33 个月内 152 个候选 CVE 中复现 38 个、生成 17 个独立验证的 exploit，单个约 14.3 个 agent 小时、321 美元 API 成本、90% 可靠性，Pixel 9/10 上 14 次试 12 次成功。
- 为什么值得看：把攻防时间尺度量化了，这是今天最有分量的一条：攻击者以「小时 + 几百美元」为单位，而同一批漏洞打进 Pixel 的中位延迟是 181 天；更关键的是 17 个被成功利用的 CVE 里只有 3 个出现在 Android 安全公告中——「看公告打补丁」存在系统性盲区。

### FATCAT: Fault Injection Attacks Targeting Chip-level Alignment
- 作者：Peter Horvath, Ilia Shumailov, Zhuoran Liu, Lukasz Chmielewski
- 分类：cs.CR, cs.AI　｜　2026-11-23　｜　[原文](https://arxiv.org/abs/2611.31129v1)
- 一句话结论：首个用物理电磁故障注入消除模型拒答的攻击：不需要软件权限、不需要模型层访问，只需物理接触，同步到 prefill 阶段打坏 GPU 上的安全关键内存事务，在机械臂上造成危险动作。
- 为什么值得看：它击穿了一个默认前提——「对齐是软件层保证」。当硬件不可信时，模型对齐不提供任何鲁棒安全保证。对机器人、边缘推理部署这是全新的威胁模型，也是把硬件容错纳入安全设计的直接理由（论文里机械臂两次试图夹住作者）。

### Are Web Agents Still Detectable? Stress-Testing Bot Defenses with Coordinated Evasion
- 作者：Parsa Nilforushan, Gemmin Sugiura, Kourosh Hashemi, Peiman Zhiani
- 分类：cs.CR, cs.AI, cs.LG　｜　2026-11-24　｜　[原文](https://arxiv.org/abs/2611.31962v1)
- 一句话结论：把「隐去自动化痕迹的 Chromium」与「生成式人类鼠标键盘轨迹」结合后，89% 的页面访问能绕过第三方反爬基准，比最强基线高 12 个百分点；消融显示两者缺一不可，只改一样仍会被检出。
- 为什么值得看：对防守方，这是「多信号融合」的有力实证——浏览器指纹与行为特征互补，单一维度检测必然被绕过；论文还指出「动作之间的时序」仍是有效信号。对做数据采集的一方，说明通过现成 bot 检测不等于真的像人。

## 六、趋势观察
- 「agent 作为新的攻击面」正在成为独立研究方向。今天 8 篇里 5 篇直接以 agent 为对象（skill 供应链、群聊隐私、权限清单、web agent 规避、自动利用 agent），重心明显从「模型对齐」移向「系统编排层」——而后者恰恰是工程实践中防护最薄弱的地方。
- 攻防时间尺度在系统性拉开。Aftershock 把「上游补丁 → Android exploit」压缩到 14 个 agent 小时、321 美元，而同一批漏洞的修复中位延迟 181 天；瓶颈已经不在技术，而在公告、评估、推送这套组织流程。
- 硬件与物理层重新进入威胁模型。FATCAT 用电磁故障注入绕开对齐并造成真实物理危险，说明「对齐 = 软件保证」这个前提正在被打破；机器人、边缘 AI 的部署方需要把硬件容错写进安全设计，而不是只做提示词层防护。
